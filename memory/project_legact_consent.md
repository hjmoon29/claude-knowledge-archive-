## 핵심 문제
미동의 기기의 자동 재연결(매초)과 재페어링 접속을 서버(TCP)가 구분 불가능.
구분 정보는 앱만 보유. 추가 기능 없이는 미동의→재동의 복귀 불가.

**관련 Wiki**: https://wiki.coway.com/pages/viewpage.action?pageId=363668062 (CWIOTPLATFORM 스페이스)

## 해결안 요약 (4안)

**1안 (추천)** — 재페어링 구간 통행마커 + 등록완료 시 해제 (gRPC 2종)
- 재페어링 진입 시 앱이 서버에 알림 → 통행마커 SET (TTL = 페어링 최대 시간)
- 블랙리스트 유지한 채 마커 있으면 통과 허용
- 등록 완료 시 차단 해제, 이탈 시 TTL 만료로 자동 복귀
- 보완: 정기 대사(배치) 필수 — 동의 원장 ↔ Redis 블랙리스트 주기 비교

**2안** — 벤더 펌웨어 기능 추가 (답변 대기 중)
- 2-a: 연결끊기 명령 (재연결 자체 중단)
- 2-b: CA 인증서 삭제 명령 (TLS 핸드셰이크 차단, 재페어링 시 자동 복귀)
- 제약: 펌웨어 추가 필요, 기존 기기 FOTA 필요

**3안** — 연결 허용 + 서버 수집만 게이트
- 차단 없이 패킷 수신 후 폐기, 동의 완료 시만 리포트 수집
- 법무 판단 필요 (미동의 기기 패킷 수신 허용 여부)

**4안** — 동의 팝업 시점 즉시 차단 해제 (gRPC 1종)
- 가장 단순하나 기획 요건 변경 필요 ("팝업 동의 = 수집 시작" 으로 변경)
- 법무 판단 필요

## 최종 결정 (2026-08-11, 법무팀 승인 완료)

**채택 정책: 3안 — 수면 리포트 데이터만 민감정보, 서버 수신 후 파기 데이터는 민감정보 아님**

### 민감정보 범위
- **민감정보 O**: 수면 리포트 데이터 (분석·저장되는 수면 측정값)
- **민감정보 X**: 서버에 수신되지만 즉시 파기되는 데이터 (기기 식별용 첫 패킷 등)

### 동의/철회 정책
- 동의 철회 시 → **제품 삭제 처리** (연결 끊김 처리 없음)
- 동의/철회 기준: **계정(Account) 단위**
- 여러 대 제품 사용 중인 경우 → 동의/철회 시 **일괄 적용 (일괄 삭제 처리)**

**Why:** 서버 수신 자체를 막을 수 없는 구조적 한계 + 법무 승인 기반으로 민감정보 범위를 리포트 데이터로 한정
**How to apply:** 기획서 작성 시 위 정책 기준으로 동의/철회 플로우 및 제품 삭제 시나리오 정의 필요
